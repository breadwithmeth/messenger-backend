# Telegram AI-боты (сценарий: адрес → магазин → телефон → корзина → заказ)

AI-боты Telegram принимают заказы у клиентов без участия оператора:

```
/start ──► возраст 21+ ──► адрес ──► геокодинг ──► ближайший магазин ──► телефон ──► корзина (AI) ──► подтверждение ──► BotOrder
                │                                                             │
        кнопки «Да, мне 21+»/«Нет»   кнопка «Поделиться номером» или текстом  │   «оператор» ──► живой оператор
```

- **Рекомендации «в пару»**: после добавления товара бот показывает 2–3 подходящих дополнения **кнопками** (закуски к пиву, сыр/шоколад к вину, миксеры к крепкому) — только из наличия выбранного магазина, без повторов, если пара уже в корзине. Работает и через кнопки выбора, и через AI (`add_to_cart`/`set_qty`).
- **Возраст 21+**: при первом диалоге бот запрашивает подтверждение (кнопки или «да»/«нет»). Без подтверждения заказ не принимается (гейт также стоит при оформлении). Подтверждение сохраняется между сессиями — повторно не спрашивается. Отказ → вежливый отказ.
- **Голосовые запрещены**: бот не обрабатывает голосовые — отвечает просьбой написать заказ текстом.
- **Общие запросы** («красное вино к ужину»): бот задаёт не больше 2–3 коротких уточняющих вопросов (сухое/полусладкое, бюджет, страна) — по одному за раз, затем `search_items` c `"limit": 3` → 2–3 подходящих товара из наличия кнопками.
- **Бот — «Гоша»**: живой продавец-консультант (реагирует на выбор, предлагает закуски, короткие ответы с эмодзи). Характер задаётся системным промтом, дополнить можно через `aiSystemPrompt` бота.
- **Телефон**: запрашивается после подтверждения магазина нативной Telegram-кнопкой «Поделиться номером» (один тап) или текстом (+7 705 123 45 67, 8705..., и т.п.). Можно ответить «позже» — тогда бот спросит при оформлении. Контактом можно поделиться в любой момент — бот запомнит. Телефон хранится в `BotDialog.phone` и попадает в `BotOrder.phone`, сводку заказа и уведомление операторам.
- Токены ботов хранятся в БД (`TelegramBot`), запуск — long-polling, как у обычных ботов поддержки.
- AI-режим включается **флагом `aiEnabled`** на конкретном боте — остальные боты работают как раньше.
- Вся переписка (входящие и ответы AI) сохраняется в `Chat`/`Message` — операторы видят её в существующем UI.
- Модель: `qwen2.5:7b` на Ollama-совместимом сервере `nssl.drawbridge.kz` (`/api/chat`, `format: "json"`).
- Заказ сохраняется в таблицу `BotOrder` (статус `new`) + уведомление операторов по Socket.IO (`bot_order_created`).

⚠️ Важно: боты подхватываются из БД **только при старте сервера** (`startAllTelegramBots()`). Бот, добавленный после деплоя, нужно запустить вручную: `POST /api/telegram/bots/:botId/start`.

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `AI_BOT_BASE_URL` | `https://nssl.drawbridge.kz` | Ollama-совместимый AI-сервер |
| `AI_BOT_API_KEY` | — | Bearer-токен AI-сервера (**обязательна**) |

| `AI_BOT_HTTP_RETRY_COUNT` | `2` | Ретраи для «Налив» (5xx/429/сеть) |

## Включение AI-бота

1. Создать бота у @BotFather, получить токен.
2. Зарегистрировать бота с AI-режимом:

```bash
curl -X POST https://bm.drawbridge.kz/api/telegram/organizations/1/bots \
  -H "Authorization: Bearer <JWT>" \
  -H "Content-Type: application/json" \
  -d '{
    "botToken": "123456:ABC-DEF...",
    "welcomeMessage": "👋 Привет! Я ассистент доставки. Напишите ваш адрес...",
    "aiEnabled": true,
    "aiModel": "qwen2.5:7b",
    "aiSystemPrompt": "необязательные доп. инструкции боту"
  }'
```

3. Запустить: `POST /api/telegram/bots/:botId/start` (или `autoStart`).
4. В Telegram написать боту `/start`.

Включение/отключение AI-режима на работающем боте: `PUT /api/telegram/bots/:botId` с `{"aiEnabled": true|false}` — перезапуск бота не требуется (флаг читается из БД на каждое сообщение).

## Сценарий диалога

| Состояние (`BotDialog.state`) | Что делает бот |
|---|---|
| `awaiting_age_confirm` | Подтверждение возраста 21+: кнопки «Да, мне 21+» / «Нет» или «да»/«нет» текстом. Отказ → вежливый отказ, заказ невозможен. |
| `awaiting_address` | Просит адрес. Геокодит через `njt25.naliv.kz/api/addresses/search`. Несколько совпадений → нумерованный список. |
| `awaiting_store_confirm` | Показывает ближайший магазин (гаверсинус по `lat/lon` из `njt25.naliv.kz/api/businesses`). «да» → дальше, «нет» → выбор из 3 ближайших. |
| `awaiting_phone` | Просит телефон: кнопка «Поделиться номером» (request_contact) или текстом. «позже» → пропустить (спросит при оформлении). |
| `shopping` | Общие запросы → до 2–3 уточняющих вопросов → `search_items` с `limit` → товары кнопками. Голосовые игнорируются (просьба написать текстом). |
| `shopping` | Поиск товаров (`/api/items/search?name=...&business_id=...`), добавление в корзину, акции учитываются в цене. Команды: «корзина», «оформить», «оператор». |
| `confirming_order` | Сводка заказа (магазин, адрес, позиции, доставка, итого). «да» → `BotOrder` в БД, «нет» → назад в корзину. |

### Выбор товаров — инлайн-кнопками

Результаты поиска бот показывает **списком с инлайн-кнопками**: один тап = +1 штука в корзину (с учётом `quantity_step`). Выбор позиции кнопкой исключает путаницу «номер из списка = количество». Под списком и корзиной — кнопки:

| Кнопка | callback | Действие |
|---|---|---|
| `1. Corona Extra · 990 ₸` | `add:<item_id>` | Добавить 1 шт в корзину |
| `Чипсы Cheetos · 600 ₸` | `add:<item_id>` | Рекомендация «в пару» — добавить в корзину |
| `🛒 Корзина` | `cart` | Показать корзину |
| `✅ Оформить` | `checkout` | К оформлению (проверит возраст и телефон) |
| `✅ Да, оформляем` / `❌ Нет` | `confirm_order` / `cancel_order` | Подтверждение заказа |
| `✅ Да, мне 21+` / `❌ Нет` | `age_yes` / `age_no` | Подтверждение возраста |

### AI-протокол (состояние `shopping`)

Модель обязана отвечать строго JSON-объектом (Ollama `format: "json"` + системный промт):

```json
{"action": "search_items", "query": "хайнекен"}
{"action": "add_to_cart", "item_id": 31117, "qty": 2}
{"action": "set_qty", "item_id": 31117, "qty": 2}
{"action": "remove_from_cart", "item_id": 31117}
{"action": "clear_cart"}
{"action": "show_cart"}
{"action": "checkout"}
{"action": "handoff"}
{"action": "reply", "reply_text": "Что-нибудь ещё?"}
```

**`add_to_cart` vs `set_qty`** (частая ошибка, закрыта отдельно):
- `add_to_cart` — «ещё», «плюс», «добавь» → прибавить к имеющемуся («ещё два ягеря» при 1 шт → 3 шт)
- `set_qty` — «два ягеря», «хочу 3», «сделай 2» → установить **итоговое** количество

**Порции**: `qty` в протоколе — количество **порций**. Размер одной порции = `quantity_step` шт товара (у большинства товаров порция = 1 шт). 1 тап кнопки = +1 порция. В корзине хранятся штуки (`qty = порции × quantity_step`), в заказе идут штуки, кламп по остатку — по целым порциям (`floor(amount / step)`). Для порционных товаров корзина показывает «8 шт (2 порц. × 4 шт)».

Бэкенд исполняет действия. Список товаров после `search_items` рендерит **сам бэкенд** (кнопки), модель его не описывает. Товар для `add_to_cart` валидируется по кэшу результатов поиска (`BotDialog.lastSearchItems`, до 50 позиций) и остаткам на складе. Если модель ответила не-JSON — текст отправляется клиенту как есть (fallback).

### Переход на оператора

Ключевые слова («оператор», «менеджер», «живой человек», …) в **любом** состоянии:
- `BotDialog.handedOff = true` — AI больше не отвечает;
- чат получает `status: new`, `priority: high` + запись в `TicketHistory` — операторы видят его в очереди.

## Интеграция с аккаунтами «Налив» (/api/telegram-bot/*)

Когда клиент делится телефоном, бот **привязывает его Telegram к аккаунту «Налив»** (`POST /api/telegram-bot/auth/link` — по `login`-телефону; если пользователь не найден, создаётся вместе с картой лояльности). JWT и `session_token` сохраняются в `BotUser`.

- Привязка идёт параллельно диалогу и не блокирует сценарий; 409 (Telegram уже у другого аккаунта) — клиенту подсказка.
- **Отслеживание статусов** (`botOrderTracker.ts`): каждые 60 сек (`BOT_ORDER_POLL_INTERVAL_MS`) опрашивается `/orders/active` для всех привязанных клиентов; при смене статуса клиенту приходит сообщение в Telegram + событие операторам `bot_order_status_changed`. Трекер стартует с сервером.

### Отправка заказа в «Налив» (`POST /api/telegram-bot/orders/create`)

Полный цикл оформления без онлайн-оплаты:

1. **Чекаут**: `POST /api/delivery/check {lat, lon, business_id}` — проверка зоны и **реальная цена доставки** (`data.price`, например 1040 ₸ вместо базовых 30 ₸). Вне зоны → предложение сменить адрес.
2. Если геокодер не вернул номер дома — бот просит написать его сообщением.
3. Подтверждение («✅ Да, оформляем») → `orders/create`: `user_id` из `BotUser`, позиции в штуках (`amount = qty`), адрес (street/house/lat/lon — сохраняется в адресах пользователя). Цены берёт сервер — акции применяются автоматически.
4. **Успех (201)**: `BotOrder.status = 'sent'` + `nalivOrderId/Uuid`, клиенту — реальная сумма к оплате (`total_sum` с доставкой) и статусный трекинг: `66 ⏳ → 0 🆕 → 1 ✅ → 2 📦 → 3 🚗 → 4 доставлен`.
5. **Fallback**: «Налив» недоступен / клиент не привязан → заказ сохраняется локально (`status = 'new'`), операторам уходит `bot_order_created` с пометкой «НЕ отправлен в „Налив"». Заказы не теряются.
6. Оплата: заказ создаётся без `payment_type_id` → статус 66 (AWAITING_PAYMENT); оплата при получении или оператором (ботовские платёжные эндпоинты — по мере появления документации).

| Метод клиента (`telegramBotClient.ts`) | Эндпоинт |
|---|---|
| `linkTelegramAccount` | `POST /api/telegram-bot/auth/link` |
| `unlinkTelegramAccount` | `POST /api/telegram-bot/auth/unlink` |
| `getUserByTelegram` | `GET /users/by-telegram/:id` |
| `getUserByPhone` | `GET /users/by-phone/:phone` |
| `getActiveOrders` | `GET /orders/active?telegram_id=` |
| `getOrderDetails` | `GET /orders/:id?telegram_id=` |
| `checkDelivery` | `POST /api/delivery/check` |
| `createNalivOrder` | `POST /api/telegram-bot/orders/create` |

Авторизация — заголовок `X-Bot-Key: <TELEGRAM_BOT_API_KEY>` (env). Модели: `BotUser` (telegramUserId ↔ nalivUserId, token, чат для уведомлений), `BotOrderTracking` (последний известный статус), `BotOrder.nalivOrderId/Uuid` (связь с заказом в «Налив»), `BotDialog.addressStreet/addressHouse/deliveryPrice`.

## Модель данных

- **`TelegramBot`**: `aiEnabled`, `aiModel` (переопределение модели для бота), `aiSystemPrompt` (кастомный промт).
- **`BotDialog`** (1:1 с `Chat`): состояние сценария, подтверждение возраста (`ageConfirmed`), адрес (`addressLabel/Lat/Lon/Street/House`), телефон (`phone`), цена доставки (`deliveryPrice`), магазин (`businessId/Name`), кандидаты для выбора, кэш поиска, корзина (`cart` JSON), `handedOff`.
- **`BotOrder`**: организация, чат, магазин, адрес, телефон клиента (`phone`), позиции (`items` JSON), `totalPrice`, `deliveryFee`, `status` (`new` → `sent` → `confirmed`/`cancelled`), `nalivOrderId/Uuid` (ID заказа в «Налив»), `telegramChatId`.
