# Telegram AI-боты для приёма заказов (сценарий: приветствие → адрес → ближайший магазин → корзина → заказ)

## Архитектура

Используем существующий мультиботный рантайм (`src/services/telegramService.ts`): токены в БД, long-polling. Новый режим включается флагом `aiEnabled` на конкретном боте — существующие боты операторов не затрагиваются. Все диалоги по-прежнему пишутся в `Chat`/`Message`, поэтому операторы видят их в текущем UI.

**Проверенные API:**
- `https://nssl.drawbridge.kz` — Ollama-совместимый (`/api/tags`), модель **qwen2.5:7b**, Bearer-токен
- `https://njt25.naliv.kz/api/addresses/search` — геокодер Photon: `label`, `geometry.coordinates = [lon, lat]`
- `https://njt25.naliv.kz/api/businesses?page=1&limit=1000` — магазины с `lat/lon/delivery_service_fee`
- `https://njt25.naliv.kz/api/items/search?name=...&business_id=...` — товары: `item_id/name/price/amount/unit/promotions`

## 1. Prisma schema + миграция

**`TelegramBot`** — новые поля:
- `aiEnabled Boolean @default(false)` — режим AI-ассистента
- `aiModel String?` — переопределение модели для бота (по умолчанию из env)
- `aiSystemPrompt String?` — кастомный промт сценария

**Новая модель `BotDialog`** (состояние диалога, 1:1 с Chat):
- `chatId Int @unique`, `state String` (`awaiting_address` | `awaiting_store_confirm` | `shopping` | `confirming_order`)
- `addressLabel/addressLat/addressLon` — подтверждённый адрес
- `businessId/businessName` — выбранный магазин
- `candidateAddresses Json?`, `candidateBusinesses Json?` — варианты для выбора клиентом
- `lastSearchItems Json?` — кэш последней выдачи поиска (для валидации item_id)
- `cart Json?` — `[{itemId, name, price, qty, unit}]`
- `handedOff Boolean @default(false)` — диалог передан оператору, AI молчит

**Новая модель `BotOrder`** (оформленный заказ — пока хранится в БД со статусом `new`, отправка наружу добавим позже по вашим данным):
- `organizationId`, `chatId`, `businessId/businessName`, `address/addressLat/addressLon`
- `items Json`, `totalPrice`, `deliveryFee`, `status String @default("new")`
- связи с `Organization` и `Chat`; индекс `[organizationId, status]`

Команда: `npx prisma migrate dev --name telegram_ai_bots` (+ обратные связи `botDialog`/`botOrders` на `Chat`, `botOrders` на `Organization`).

## 2. Новые файлы

**`src/config/nalivConfig.ts`** — env: `NALIV_API_BASE_URL` (default `https://njt25.naliv.kz`), `AI_BOT_BASE_URL` (default `https://nssl.drawbridge.kz`), `AI_BOT_API_KEY`, `AI_BOT_MODEL` (default `qwen2.5:7b`).

**`src/integrations/naliv/nalivClient.ts`** (по паттерну workforce-интеграции, axios, таймаут/ретраи):
- `searchAddresses(query)` → `[{label, lat, lon, city}]`
- `getBusinesses()` → все магазины (кэш в памяти на 5 мин)
- `searchItems(name, businessId, page, limit=40)` → товары (фильтр `visible=1`)
- `findNearestBusinesses(lat, lon, limit)` — haversine-дистанция, сортировка по возрастанию
- Типы `NalivAddress/NalivBusiness/NalivItem`

**`src/services/aiChatClient.ts`** — Ollama-native клиент (axios):
- `chat(messages, {model, temperature})` → `POST {AI_BOT_BASE_URL}/api/chat`, `{model, messages, stream: false}`, Bearer-заголовок
- `listModels()` → `GET /api/tags`
- `checkHealth()`

**`src/services/botDialogService.ts`** — ядро, state machine:

- `handleBotStart()` — при `/start` у AI-бота: создать `BotDialog`, отправить приветствие и попросить адрес → `awaiting_address`
- `handleBotUserMessage()` — маршрутизация по состоянию:
  - **Ключевые слова «оператор»/«менеджер»** → `handedOff=true`, чат в статус `new` для операторов, уведомление через Socket.IO, ответ «передаю оператору»
  - **`awaiting_address`**: выбор цифрой из кандидатов или геокодинг текста; 0 результатов → переспросить; 1 → сразу; несколько → нумерованный список (до 3). Затем `findNearestBusinesses` → «Ваш адрес: X. Ближайший магазин: Y (N км). Верно?» → `awaiting_store_confirm`
  - **`awaiting_store_confirm`**: «да» → `shopping`; «нет» → показать 2–3 ближайших магазина на выбор
  - **`shopping`**: текст идёт в AI (qwen2.5:7b) со строгим JSON-протоколом (см. ниже)
  - **`confirming_order`**: «да» → создать `BotOrder` (status `new`), уведомить операторов через Socket.IO, итог клиенту; «нет» → вернуться в `shopping`
- **AI JSON-протокол** (работает с любой чат-моделью, не требует tool-calling): модель обязана отвечать строго `{"action": "...", "query"/"item_id"/"qty"/"reply_text": ...}` c действиями:
  - `search_items {query}` → бэкенд ищет товары, показывает клиенту нумерованный список с ценами (кэширует в `lastSearchItems`)
  - `add_to_cart {item_id, qty}` / `remove_from_cart {item_id}` / `clear_cart` / `show_cart` — cart-операции с валидацией item_id по кэшу и остаткам (`amount`), формат вывода с суммой + `delivery_service_fee`
  - `checkout` → переход в `confirming_order` с полной сводкой (магазин, адрес, позиции, доставка, итого)
  - `reply {reply_text}` — просто текст клиенту
  - Цикл: максимум 3 вызова модели на сообщение клиента, результаты действий скармливаются модели обратно; если JSON распарсить не удалось — отправляем сырой текст как ответ (fallback), логируем
- Cart-утилиты вынесены в чистые функции для юнит-тестов

**Изменение `src/services/telegramService.ts`:**
- `handleStartCommand`/`handleIncomingMessage`: если `bot.aiEnabled` → маршрут в `botDialogService` (входящие по-прежнему сохраняются в `Message` + socket-уведомление)
- Новая `sendBotReply(botId, chatId, text)` — отправка через Telegram + persist `fromMe: true` (операторы видят ответы AI в UI)
- Для нетекстовых входящих (фото и т.п.) у AI-бота — вежливая просьба писать текстом
