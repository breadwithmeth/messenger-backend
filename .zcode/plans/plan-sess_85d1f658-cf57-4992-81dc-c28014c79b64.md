# Обновление Baileys и сверка с документацией

## Контекст (результаты сверки)
- Установлен `@whiskeysockets/baileys 7.0.0-rc13`; на npm latest — **7.0.0-rc14** (fix: Long-импорт, фикс tc-token для profilePictureUrl — используется в contactController, новый android-браузер, bump версии WhatsApp Web). Пакет `baileys` на npm — это чужой форк, не менять имя пакета.
- Документация: baileys.wiki (migration/v7, socket-config). Проект **уже соответствует** большей части v7: ESM (`type: module`), LID-обработка (`lid-mapping.update` + `signalRepository.lidMapping.storeLIDPNMapping`), кастомный DB auth-state совместим с новыми типами ключей `lid-mapping`/`device-list`/`tctoken` (проверено по типам rc13), `remoteJidAlt`/`participantAlt`, QR из `connection.update`, сигнатура `sock.end(error)`.

## 1. Обновление пакета
- `npm install @whiskeysockets/baileys@^7.0.0-rc14`, проверить версию в lock-файле.

## 2. Правки в `src/config/baileys.ts` по документации
- **`getMessage` (строки 779–808)**: по докам тип `Promise<proto.IMessage | undefined>` — для неизвестного сообщения **обязательно возвращать `undefined`** (иначе ломается повторное шифрование при retry). Убрать фолбэки `{conversation: '...'}`; возвращать сохранённый контент только для полностью сохранённых текстовых сообщений; добавить фильтр по `remoteJid: jidNormalizedUser(key.remoteJid)` (в БД remoteJid хранится нормализованным).
- **`browser` (строка 770)**: заменить ручной кортеж `['Ubuntu','Chrome','22.04.4']` на `Browsers.ubuntu('Chrome')` (та же строка, но по докам — через константу; импортировать `Browsers`).
- **`msgRetryCounterCache`**: добавить модульный TTL-кэш (Map с TTL ~2 мин, методы get/set/del/flushAll под тип `CacheStore`, без новых зависимостей) и передать в `makeWASocket` — по докам кэш должен жить вне функции старта, чтобы счётчики retry переживали реконнекты.
- **`markOnlineOnConnect: false`** (выбор пользователя): телефон продолжает получать push-уведомления.

## 3. Чистка хвостов
- Удалить `src/services/baileysAuthStateService.ts` и `src/config/qrCache.ts` — проверено, нигде не импортируются.
- `baileys_auth_files/` фактически не существует — действий нет.
- Prisma-модель `baileysAuthState` не трогаем (миграция БД вне скоупа).

## 4. Перевод build-скрипта на ESM
Сейчас `npm run build` собирает CJS, который `require()`-ит ESM-only Baileys v7 (работает только благодаря Node 24 require(esm) — хрупко).
- Кодмод по всем `src/**/*.ts`: добавить `.js` к относительным импортам/реэкспортам (`from './x'` → `from './x.js'`; ~214 мест; проверять динамику `import()`).
- `build`: `tsc --module nodenext --moduleResolution nodenext`, в `dist/package.json` — `{"type":"module"}`.
- `jest.config.cjs`: добавить `moduleNameMapper: {'^(\\.{1,2}/.*)\\.js$': '$1'}` (ts-jest CJS).
- Dev-режим совместим: в dev-скрипте уже стоит `TS_NODE_PREFER_TS_EXTS=true` (`.js` резолвится в `.ts`).
- **Откат, если что-то не сойдётся**: оставить CJS-сборку (работает на Node ≥22.12), откатить кодмод.
